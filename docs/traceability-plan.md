# แผนฟีเจอร์: สวน → ตระกร้า → กล่อง

วิเคราะห์เชิงธุรกิจสำหรับการขยายจาก "วัดตัวอย่าง" ไปเป็น "ติดตามของจริง"
เขียน 2026-07-30

---

## 1. สิ่งที่เปลี่ยนไปจริง ๆ

ตอนนี้แอปทำ **การสุ่มตัวอย่าง** — ถ่ายรูปเดียว วัดลำไย 80 ลูก แล้วอนุมานว่าล็อตนี้
เป็นอย่างไร แต่ละรูปเป็นเอกเทศ ไม่ผูกกับอะไร

สองฟีเจอร์นี้ต้องการ **การติดตามหน่วยจริง** — ตระกร้าใบนี้ กล่องใบนั้น มีตัวตน
มีเนื้อใน และมีประวัติว่ามาจากไหน

นี่ไม่ใช่การเพิ่มหน้าจอ แต่เป็นการเปลี่ยนแบบจำลองข้อมูลทั้งหมด

### คำถามที่ต้องตอบก่อนเขียนโค้ดบรรทัดแรก

> **แอปคัดเกรดเอง หรือแอปรับรองสิ่งที่คนคัดไปแล้ว?**

| ทางเลือก | หมายความว่า | ทำได้จริงไหม |
|---|---|---|
| A. แอปบอกทีละลูกว่าเกรดอะไร | คนคัดต้องถ่ายรูปทีละลูก | ❌ ช้ากว่าใช้ตาเปล่า |
| B. แอครับรองตระกร้าที่คัดแล้ว | คัดด้วยมือ/เครื่อง แล้วสุ่มตรวจ | ✅ ตรงกับที่ทำอยู่จริง |
| C. แอปคัดจากภาพเดียวทั้งกอง | ต้องแยกของที่กองรวมกัน | ❌ ยังนับของที่ซ้อนกันไม่ได้ |

**ผมแนะนำ B** และนี่คือประเด็นสำคัญที่สุดของเอกสารนี้:

> แอปไม่ได้คัด — **แอปรับรอง**

คนหรือเครื่องคัดลำไยลงตระกร้าตามที่ทำอยู่แล้ว แอปถ่ายรูปสุ่มจากตระกร้านั้น
แล้วออกใบรับรองว่า "ตระกร้านี้เกรด AA จริง 94%" ซึ่งเป็นสิ่งที่ผู้รับซื้อต้องการ
และเป็นสิ่งที่ระบบทำได้จริงวันนี้

---

## 2. กระบวนการจริง

```
เก็บเกี่ยว → คัดที่สวน → ตระกร้า → ขนส่ง → ล้ง/โรงคัด → ตรวจสอบ → กล่อง → ผู้ซื้อ
                 ↑                                          ↑
            ฟีเจอร์ 1                                   ฟีเจอร์ 2
```

**ฟีเจอร์ 1 — ที่สวน:** คัดลงตระกร้าแยกเกรด แล้วรับรองแต่ละตระกร้า
**ฟีเจอร์ 2 — ที่ล้ง:** ตรวจซ้ำก่อนลงกล่อง จับความไม่ตรงกัน

จุดที่มีมูลค่าคือ **ความไม่ตรงกันระหว่างสองจุด** — ถ้าสวนบอก AA แต่ล้งวัดได้ A
นั่นคือข้อมูลที่ทั้งสองฝ่ายเถียงกันทุกฤดู และตอนนี้ไม่มีใครมีหลักฐาน

---

## 3. ปัญหาที่ยากที่สุด: ตระกร้าจะรู้ได้ยังไงว่าตัวเองคือใบไหน

ถ้าไม่มีตัวตน ก็ติดตามไม่ได้ ทางเลือก:

| วิธี | ข้อดี | ข้อเสีย |
|---|---|---|
| เขียนเลขแล้วพิมพ์เข้าแอป | ไม่ต้องพิมพ์ป้าย | ชาวสวนต้องพิมพ์ทุกใบ ผิดง่าย |
| QR code | มาตรฐาน สแกนง่าย | ต้องสแกนแยกอีกครั้ง |
| **ป้าย ArUco** | **กล้องอ่านได้ในภาพเดียวกับที่วัด** | ต้องพิมพ์ป้าย |

**แนะนำ ArUco** — เราอ่าน ArUco อยู่แล้ว วางป้ายตระกร้าไว้ข้างแผ่นสอบเทียบ
ถ่ายรูปเดียวได้ทั้งการวัดและรหัสตระกร้า **ชาวสวนไม่ต้องพิมพ์อะไรเลย**

ข้อควรระวัง: ต้องใช้ **dictionary คนละชุดกับแผ่น** (เช่น `DICT_5X5_100` ขณะที่
แผ่นใช้ `DICT_4X4_50`) ไม่งั้นป้ายตระกร้าอาจถูกเข้าใจผิดว่าเป็นมุมแผ่น
แล้วมาตราส่วนจะเพี้ยนทั้งภาพ

ป้ายขนาด ~40 มม. อ่านได้ที่ระยะเดียวกับที่ถ่ายแผ่น

## 4. แบบจำลองข้อมูล

```
Grower
  └── Lot            ล็อตเก็บเกี่ยว: วันที่ · แปลง · ชนิดผลไม้
        └── Basket   ตระกร้า: รหัส ArUco · เกรดที่ประกาศ · น้ำหนัก
        │     └── Measurement   ภาพสุ่มตรวจ (มีได้หลายครั้ง)
        └── Box      กล่อง: รหัส · ตระกร้าที่ใส่ · เกรดที่ตรวจซ้ำ
```

ประเด็นออกแบบที่ต้องตัดสินใจ:

**ตระกร้า → กล่อง เป็นความสัมพันธ์แบบไหน?**
- 1 ตระกร้า = 1 กล่อง → ง่าย แต่ไม่ตรงความจริง
- หลายตระกร้า → 1 กล่อง → ต้องบันทึกว่าเอาจากตระกร้าไหนบ้าง
- 1 ตระกร้า → หลายกล่อง → ต้องมีน้ำหนักคงเหลือ

**ต้องถามผู้ใช้จริงก่อน** ผมเดาให้ไม่ได้ และเลือกผิดจะแก้ยากมาก

**น้ำหนักมาจากไหน?** แอปชั่งไม่ได้ — ต้องพิมพ์เอง (เริ่มต้น) หรือต่อเครื่องชั่ง
Bluetooth (ทีหลัง) และ **คนไทยซื้อขายเป็นกิโล** ดังนั้นน้ำหนักคือสะพานเดียว
ระหว่างมิลลิเมตรที่เราวัดกับเงินที่เขาได้

## 5. แอปทำอะไรในแต่ละขั้น

### ฟีเจอร์ 1 — ที่สวน

1. เปิดล็อตใหม่: วันที่ · แปลง · ชนิดผลไม้
2. คัดลงตระกร้าตามปกติ (คนทำ ไม่ใช่แอป)
3. ถ่ายรูปสุ่มจากตระกร้า **พร้อมป้าย ArUco ของตระกร้า**
4. แอปรับรอง: *"ตระกร้า #12 — AA 94% · A 6% · เฉลี่ย 29.1 มม. · สุ่ม 62 ลูก"*
5. ใส่น้ำหนัก
6. ถ้าสัดส่วนเกรดไม่ตรงกับที่ประกาศ → **เตือนให้คัดใหม่**

### ฟีเจอร์ 2 — ที่ล้ง

1. สแกนป้ายตระกร้า → เห็นสิ่งที่สวนรับรองไว้
2. ถ่ายรูปสุ่มตรวจซ้ำ
3. เทียบ: ตรงกันไหม
4. ลงกล่อง → ผูกตระกร้ากับกล่อง
5. ออกใบรับรองกล่อง + QR ให้ผู้ซื้อเปิดดูที่มาได้

## 6. สิ่งที่ต้องระวัง

**ความคลาดเคลื่อนจะทบกัน** สุ่ม 60 ลูกจากตระกร้า 500 ลูก แล้วสรุปทั้งตระกร้า
มีความไม่แน่นอนทางสถิติ ต้องแสดง **ช่วงความเชื่อมั่น** ไม่ใช่ตัวเลขเดียว
*"AA 94% ± 3%"* ซื่อสัตย์กว่า *"AA 94%"*

**ยิ่งดูน่าเชื่อถือ ยิ่งอันตรายถ้าผิด** ใบรับรองที่มี QR code ดูเป็นทางการมาก
ถ้าการวัดคลาด 2 มม. เราจะออกใบรับรองที่ผิดทั้งตระกร้า — แย่กว่าไม่มีระบบเลย
เพราะคนจะเชื่อมัน

**การซ้อนทับยังเป็นปัญหา** ลำไยในตระกร้าเทกองซ้อนกันหมด ตอนนี้วัดได้แค่
2% เมื่อวางเบียด ต้องเกลี่ยลงถาดก่อนถ่าย — **ต้องออกแบบขั้นตอนนี้ให้ชัด**
ไม่งั้นชาวสวนจะถ่ายทั้งตระกร้าแล้วได้ผลที่ใช้ไม่ได้

**เครือข่าย** สวนมีสัญญาณเน็ต จึงไม่ต้องออกแบบให้ทำงานออฟไลน์เต็มรูปแบบ
ความช้าที่เหลือเป็นเรื่อง CPU ของเซิร์ฟเวอร์ล้วน ๆ แก้ด้วยการอัปแพ็กเกจ

**ตรวจสอบย้อนกลับเพื่อส่งออก** ถ้าเป้าหมายคือส่งออก มีมาตรฐาน GAP/ThaiGAP
ที่กำหนดว่าต้องเก็บอะไรบ้าง **ต้องไปอ่านก่อนออกแบบ** ไม่ใช่ออกแบบแล้วค่อยดู

## 7. ลำดับที่แนะนำ

| ระยะ | ทำอะไร | ผ่านได้เมื่อ |
|---|---|---|
| **0** | พิสูจน์ความแม่นกับลำไยจริง + เวอร์เนีย | bias < 0.1 มม. |
| **0.5** | แก้ disk + คิวออฟไลน์ | ข้อมูลไม่หาย |
| **1** | **ล็อต** — รวมหลายรูปเป็นล็อตเดียว + ช่วงความเชื่อมั่น | สุ่มหลายจุดได้ |
| **2** | **น้ำหนัก + ราคา** → บอกเป็นเงิน | ชาวสวนใช้ต่อรองได้ |
| **3** | **ตระกร้า** — ป้าย ArUco + รับรอง | ฟีเจอร์ 1 |
| **4** | **กล่อง** — ตรวจซ้ำ + ผูกตระกร้า | ฟีเจอร์ 2 |
| **5** | QR ให้ผู้ซื้อ | ตรวจสอบย้อนกลับได้ |

**ระยะ 1 กับ 2 ไม่ใช่ของแถม** — ล็อตคือรากฐานของตระกร้า (ตระกร้าก็คือล็อตย่อย
ที่มีตัวตน) และน้ำหนักคือสิ่งที่ทำให้ทั้งระบบมีความหมายทางการค้า
ข้ามไปทำตระกร้าเลยจะต้องกลับมารื้อ

## 8. คำถามที่ต้องถามชาวสวนจริงก่อนออกแบบต่อ

ผมตอบแทนไม่ได้ และคำตอบเปลี่ยนโครงสร้างข้อมูล:

1. ตระกร้าหนึ่งใบใส่กี่กิโล? ใช้ซ้ำหรือใช้ครั้งเดียว?
2. คัดที่สวนกี่เกรด? แยกจริงหรือแยกแค่ AA กับที่เหลือ?
3. หนึ่งกล่องมาจากกี่ตระกร้า?
4. ใครเป็นคนตรวจที่ล้ง — ชาวสวน ล้ง หรือทั้งคู่?
5. ตอนนี้เถียงกันเรื่องเกรดบ่อยแค่ไหน และเถียงกันอย่างไร?

**ข้อ 5 สำคัญที่สุด** — ถ้าไม่มีใครเถียงกัน ฟีเจอร์นี้ก็ไม่มีคนใช้
ถ้าเถียงกันทุกฤดู นี่คือฟีเจอร์ที่ขายได้
