## 1. หลักการ

```
เทลำไยลงโซนเข้า  →  เกลี่ยด้วยนิ้ว  →  ปล่อยมือ  →  วงสีขึ้นครบ  →  ปัดไปขวา  →  +N
                                                                          │
                                        ◄─────────────────────────────────┘  ทำซ้ำ
```

ตระกร้า 500 ลูก ≈ 25–30 รอบ ≈ 3–5 นาที ได้ **สำมะโนครบทุกลูก ไม่ใช่การสุ่ม**

เทียบกับตอนนี้: ถ่ายรูปเดียวได้ 80 ลูก แล้วอนุมานทั้งตระกร้า พร้อมความไม่แน่นอน ±3%

### สามอย่างที่ง่ายลงเพราะไม่ใช้เครื่อง

| | สายพาน | ใช้มือ |
|---|---|---|
| เบลอจากการเคลื่อนไหว | ต้องมีไฟ LED + ล็อกชัตเตอร์ | **หายไป — วัดเฉพาะตอนนิ่ง** |
| การติดตาม | ต้องมี motion model + ทำนายตำแหน่ง | **ของไม่ขยับ จับคู่ด้วยตำแหน่งล้วน** |
| มือเข้ามาในเฟรม | ต้องแยกมือออกจากผลไม้ | **ตัวตรวจนิ่งกันให้เอง** |
| ของที่ต้องซื้อ | สายพาน มอเตอร์ ราง ไฟ | **ขาตั้งมือถือ 1 ตัว** |

ตัวตรวจ frame-diff ตัวเดียวทำสามหน้าที่: กันมือ · กันเบลอ · ประหยัด CPU

## 3. สิ่งที่แสดงบนกล้อง

### หลักการสามข้อ

**1. โซนต้องเกาะติดแผ่นจริง ไม่ใช่ลอยกลางจอ**
วาดผ่าน homography เดียวกับที่ใช้วัด แผ่นเอียง กรอบเอียงตาม
(ตอนนี้ `MatGuide.tsx` วาดกรอบลอยกลางจอ ไม่เกี่ยวกับแผ่นเลย)

**2. สีโซนห้ามชนกับสีเกรด**
เกรดใช้ 🟢🔵🟡 อยู่แล้ว โซนจึงต้องเป็นกลาง — เข้า/ออกลงเงาจาง ๆ
**โซนวัดคือที่เดียวที่ไม่ลงเงา** สายตาจึงไปตกตรงที่มีความหมายเอง

**3. โซนต้องตอบสนอง ไม่ใช่เส้นตาย**
ตารางที่วาดนิ่ง ๆ คือของประดับ ตารางที่เปลี่ยนตามสถานการณ์คือเครื่องมือ

### แต่ละโซนเปลี่ยนหน้าตาอย่างไร

| โซน | ปกติ | เมื่อมีเหตุ |
|---|---|---|
| **เข้า** | เงาจาง + เส้นประ + "วางลำไยตรงนี้" | มีของอยู่ → "เกลี่ยเข้าโซนวัด" |
| **วัด** | ใส ไม่มีเงา | มือขยับ → เบลอเบา ๆ + "กำลังรอนิ่ง…" |
| | | นิ่งแล้ว → วงสีขึ้นพร้อมตัวเลข |
| | | ติดกัน → ⚠ วงสีส้มคลุมกลุ่ม + "เกลี่ยก่อน" |
| **ออก** | ลายทาง + ลูกศร ▶▶ | ของข้ามเข้ามา → กะพริบ + ตัวนับเด้ง |

### สองอย่างที่ขาดไม่ได้

**เสียงและการกะพริบตอนนับ** — ชาวสวนปัดแล้วต้องรู้ทันทีว่าเข้าหรือไม่เข้า
โดยไม่ต้องจ้องตัวเลข **ตัวนับที่พลาดแบบเงียบ ๆ แย่กว่าไม่มีตัวนับ**

**ปุ่มแก้ไข** — มันจะนับผิด ต้องมีทางแก้ตั้งแต่วันแรก ไม่ใช่รอให้ผู้ใช้บ่น

## 4. โซนบนแผ่นพิมพ์

ถ้าพิมพ์เส้นโซนลงบนแผ่นด้วย ชาวสวนเห็นได้โดยไม่ต้องมองจอ และหน้าจอกับของจริงตรงกัน

⚠️ **ความเสี่ยง** — เคยเจอแล้วว่าเส้นกริดที่พิมพ์ในพื้นที่วัดถูกนับเป็นผลไม้
(Otsu แยกฮิสโทแกรมชั้นเดียวเสมอ ต้องใส่ `EMPTY_SHEET_SATURATION` กัน)

ข้อกำหนดถ้าจะพิมพ์:
- **เส้นบางสีเทาอ่อนเท่านั้น** ใช้ `GRID_C` เดิม ห้ามลงพื้นสีหรือแรเงา
- ตัวหนังสือกำกับอยู่**นอก**พื้นที่วัด
- **ต้องรันเทสต์แผ่นเปล่าซ้ำ** ก่อนพิมพ์จริง ไม่ใช่พิมพ์แล้วค่อยรู้

## 5. Tracker

ของไม่ขยับ จึงง่ายกว่าการติดตามทั่วไปมาก — ไม่ต้องมีแบบจำลองความเร็ว

| พารามิเตอร์ | ค่าเริ่มต้น | เหตุผล |
|---|---|---|
| จับคู่ ID | centroid ใกล้สุดภายใน **10 มม.** | ของนิ่ง เผื่อไว้เยอะแล้ว |
| ตรวจนิ่ง | ย่อ 64×64 เทา · ผลต่างเฉลี่ย < 2/255 ติดกัน **300 มส.** | ต้องจูนกับของจริง |
| ถอนคืนได้ภายใน | **8 วินาที** | ดูข้อ 6 |

**ของที่หายแล้วกลับมาที่เดิม = ID เดิม** เพราะตำแหน่งตรงกัน นี่คือเหตุผลที่โหมดมือ
แข็งแรงกว่าสายพานมาก

### พิสูจน์แล้วว่า 10 มม. พอ

สมมติฐานที่ทั้งโหมดนี้ตั้งอยู่บน: ตำแหน่งเป็น**มิลลิเมตรบนแผ่น** จึงไม่ขยับตามกล้อง
ทดสอบด้วยการเรนเดอร์ฉากเดิมโดยขยับกล้อง:

| ขยับกล้อง | จับคู่ได้ | เลื่อนเฉลี่ย | เลื่อนสูงสุด |
|---|---|---|---|
| ไม่ขยับ | 64/64 | 0.00 มม. | 0.00 มม. |
| เลื่อนข้าง 10 มม. | 64/64 | 0.50 มม. | 1.17 มม. |
| เลื่อนข้าง 30 มม. | 64/64 | 1.19 มม. | 1.84 มม. |
| เปลี่ยนความสูง 40 มม. | 64/64 | 0.44 มม. | 0.85 มม. |
| **ขยับ 30 มม. + สูง 40 มม. พร้อมกัน** | **64/64** | 1.15 มม. | **2.06 มม.** |

ชนขาตั้งแรง ๆ ยังเลื่อนแค่ 2 มม. **มีที่เหลืออีก 5 เท่าก่อนถึงรัศมีจับคู่**

## 6. State machine (ตามที่สร้างจริง)

ระหว่างเขียนโค้ดพบว่าแบบที่ออกแบบไว้เดิมใช้ไม่ได้ สองข้อ:

**ข้อแรก — "เห็นลูกเข้าโซนออก" เกิดขึ้นไม่ได้เลย**
ลูกที่ขยับจากโซนวัดไปโซนออกเดินทาง 150 มม. ซึ่งไกลเกินรัศมีจับคู่ 10 มม.
tracker จึงถือว่าเป็นคนละลูก กฎนี้เป็นโค้ดที่ไม่มีวันทำงาน **ตัดทิ้ง**

**ข้อสอง — รอ 3 วินาทีแล้วค่อยนับ ช้าเกินไป**
ปัดแล้วรอ 3 วินาทีกว่าตัวเลขจะขยับ คนใช้จะไม่รู้ว่าเข้าหรือไม่เข้า

ทางแก้มาจากข้อสังเกตเดียว: **`update()` ถูกเรียกเฉพาะตอนฉากนิ่งเท่านั้น**
มือพาดอยู่บนแผ่น = ไม่นิ่ง = ไม่มีเฟรมเลย ดังนั้น **ลูกที่หายไปจากเฟรมที่นิ่งแล้ว
คือหายไปจริง ไม่ใช่ถูกมือบัง** จึงนับได้ทันทีโดยไม่ต้องรอนาฬิกา

```
        ปรากฏในโซนใดก็ได้
              │
              ▼
            NEW ─────────► อยู่ในช่องวาง / ถูกบังอยู่ → ยังไม่วัด
              │
              │ อยู่ในโซนวัด และเห็นเต็มใบ
              ▼
         MEASURED ────────► เก็บค่าที่ใหญ่ที่สุด · แสดงวงสีเกรด
              │
              │ ไม่อยู่ในเฟรมที่นิ่งถัดไป
              ▼
         COUNTED ✅ +1 ──────┐
              │              │ กลับมาที่เดิมภายใน 8 วิ
              │              ▼
              │         ถอนคืน −1 → กลับเป็น MEASURED
              │
              │ พ้น 8 วินาที
              ▼
           ปลด ID


   NEW ที่หายไป (ไม่เคยวัด) → ทิ้ง ไม่นับ
```

### กฎกันนับซ้ำ

1. **ต้องผ่าน `MEASURED` ก่อน** — ลูกที่วางในช่องวางแล้วหยิบกลับ ไม่เคยวัด จึงไม่นับ
2. **นับแล้วรายงานครั้งเดียว** ฝั่งเซิร์ฟเวอร์ยังกันซ้ำด้วย tracker id อีกชั้น
   ส่งซ้ำเพราะเน็ตหลุดจึงเพิ่มยอดไม่ได้
3. **ถอนคืนอัตโนมัติ** ถ้าลูกโผล่กลับมาที่เดิม แปลว่ามันไม่เคยไปไหน —
   นี่คือสิ่งที่กันไม่ให้ "detector พลาดหนึ่งเฟรม" กลายเป็นการนับซ้ำ
4. **ลูกที่ถูกบังบางส่วน (occluded) ไม่นับ** ขอบถูกตัด ค่าที่วัดได้ต่ำกว่าจริง

> **ยอมนับขาดดีกว่านับเกิน** — นับขาดผู้ใช้เห็นแล้วปัดกลับมาใหม่ได้
> นับเกินไม่มีใครรู้ นี่คือเหตุผลที่ปุ่มถอนคืนอยู่บนหน้าจอหลัก ไม่ใช่ในหน้าตั้งค่า

## 8. เรื่องความแม่น — วัดใหม่แล้ว ดีกว่าที่เขียนไว้เดิม

ผมเคยเขียนว่าโหมดสดคลาด **+0.43 มม.** ตัวเลขนั้นมาจากการเรนเดอร์ภาพเต็มความละเอียด
แล้วย่อลง ซึ่ง**ไม่ใช่สิ่งที่กล้องพรีวิวทำ** — กล้องจับที่ความละเอียดนั้นตั้งแต่แรก

วัดใหม่โดยเรนเดอร์ที่ 1280×960 ตรง ๆ ที่ 2.5 px/มม. ครบทั้ง 9 เงื่อนไข:

| สูง | d จริง | นับได้ | เฉลี่ย | bias | sd |
|---|---|---|---|---|---|
| 460 มม. | 24 / 28 / 32 | 81/81 · 64/64 · 49/49 | 23.93 · 27.88 · 31.90 | −0.07 · −0.12 · −0.10 | 0.20 |
| 520 มม. | 24 / 28 / 32 | 81/81 · 64/64 · 49/49 | 24.06 · 28.01 · 31.90 | +0.06 · +0.01 · −0.10 | 0.21 |
| 600 มม. | 24 / 28 / 32 | 81/81 · 64/64 · 49/49 | 24.10 · 27.99 · 31.91 | +0.10 · −0.01 · −0.09 | 0.20 |

**bias อยู่ในช่วง −0.12 ถึง +0.10 มม. · sd 0.2 มม. · นับครบทุกลูกทุกกรณี**

เทียบกับเส้นแบ่งเกรดที่ห่างกัน 3 มม. นี่คือ**พอสำหรับตัดเกรดจริง** ไม่ใช่แค่ช่วยดู

### ผลที่ตามมาสามข้อ

1. **ธง "ก้ำกึ่ง" แคบลงได้** จาก ±0.5 มม. เหลือ **±0.3 มม.** (≈1.5 sd) —
   ของที่ต้องถ่ายนิ่งซ้ำจะน้อยลงมาก
2. **วงกลมอ้างอิงบนแผ่นยังไม่ต้องทำ** ผมเสนอไว้เพื่อหัก bias +0.43 ออก
   ถ้า bias ≈ 0 ก็ไม่มีอะไรให้หัก **เก็บไว้เป็นทางสำรอง** ถ้าลำไยจริงแสดง bias
3. **8 px/มม. ห้ามใช้กับเฟรมพรีวิว** — วัดได้ +0.4 มม. และช้ากว่า 10 เท่า (2950 มส.)
   เพราะเป็นการขยายภาพเกินข้อมูลที่มีจริง ยิ่งละเอียดไม่ได้แปลว่ายิ่งแม่น

### ⚠️ สิ่งที่ตัวเลขนี้ยังไม่ได้พิสูจน์

ทั้งหมดนี้คือทรงกลมสังเคราะห์ที่เรนเดอร์ด้วยแบบจำลองเรขาคณิตชุดเดียวกับที่ pipeline
ใช้แก้ **มันจึงพิสูจน์ว่าโค้ดสอดคล้องกับตัวเอง ไม่ได้พิสูจน์ว่าตรงกับลำไยจริง**
ลำไยมีขั้ว ไม่กลมสนิท ผิวด้าน มีเงาที่ฐาน — ขั้น 6 เท่านั้นที่ตอบได้
