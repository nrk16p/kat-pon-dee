# Real-time grading บนมือถือ — เปิดกล้องแล้วเห็นผลสด

เป้าหมายตามที่ผู้ใช้ระบุ: เปิดแอป → เปิดกล้อง → วางลำไยบนแผ่น →
**เห็นเกรดทุกลูกสดบนหน้าจอ ไม่ต้องกดวิเคราะห์**

วัดจริงบน Mac (1 CPU) · ลำไย 49 ลูกวางแยกกัน · 2026-07-30

## 1. ข้อมูลที่เปลี่ยนคำตอบ

ผมเคยประเมินว่ายากมาก จนได้วัดที่ความละเอียด **ภาพพรีวิวจากกล้อง** ซึ่งเป็น
สิ่งที่ระบบสดจะได้จริง (ไม่ใช่ภาพถ่ายเต็ม 12 MP):

| พรีวิว | มาร์กเกอร์ | เวลาหามาร์กเกอร์ | ขนาดมาร์กเกอร์ | แยกผลไม้ | เจอ | คลาด |
|---|---|---|---|---|---|---|
| 1080p | 4/4 | 13.6 ms | 112 px | 187 ms | 49/49 | +0.50 มม. |
| 720p | 4/4 | **5.9 ms** | 75 px | 184 ms | 49/49 | +0.47 มม. |
| 540p | 4/4 | 2.9 ms | 56 px | 187 ms | 49/49 | +0.43 มม. |
| 360p | 4/4 | 2.1 ms | 37 px | 190 ms | 49/49 | +0.30 มม. |

**สามข้อค้นพบ:**

1. **มาร์กเกอร์อ่านได้ครบ 4/4 แม้ที่ 360p** (มาร์กเกอร์เหลือ 37 px)
2. **หามาร์กเกอร์เร็วมาก — 6 ms ที่ 720p** บนมือถือผ่าน WASM ช้ากว่า 3–10 เท่า
   ก็ยังได้ **15–50 fps**
3. การแยกผลไม้กินเวลา ~187 ms คงที่ — **นี่คือคอขวดเดียว**

## 2. กุญแจสำคัญ: ฉากไม่ได้เคลื่อนไหว

ลำไยวางนิ่งอยู่บนแผ่นบนโต๊ะ **สิ่งที่ขยับคือมือที่ถือกล้อง ไม่ใช่ผลไม้**

จึงไม่ต้องคำนวณใหม่ทั้งหมดทุกเฟรม:

```
ทุกเฟรม (30 fps)          หามาร์กเกอร์ 6 ms → อัปเดต homography
                          → ฉายวงกลมที่จำไว้ลงตำแหน่งใหม่  (< 1 ms)
                          → วงกลมเกาะติดผลไม้ขณะขยับกล้อง

ทุก ~1 วินาที (เบื้องหลัง) แยกผลไม้ใหม่ 187 ms ใน Web Worker
                          → อัปเดตขนาดและเกรด
```

**ผลที่ชาวสวนเห็น:** เปิดกล้อง วงกลมขึ้นภายในวินาทีเดียว เกาะติดลำไยตลอดขณะขยับ
มือถือ หยิบลูกออก → วงหายไปในหนึ่งวินาที **ไม่ต้องกดอะไรเลย**

นี่คือ real-time ในมุมของผู้ใช้ แม้ว่าการวัดจริงจะทำแค่วินาทีละครั้ง

## 3. ราคาที่ต้องจ่าย: ความแม่นลดลง

> **แก้ไข 2026-07-30** — ตัวเลข +0.43 มม. ในตารางข้อ 1 มาจากการเรนเดอร์ภาพเต็ม
> ความละเอียดแล้วย่อลง ซึ่งไม่ใช่สิ่งที่กล้องพรีวิวทำ วัดใหม่โดยเรนเดอร์ที่
> 1280×960 ตรง ๆ ได้ **bias −0.12 ถึง +0.10 มม. · sd 0.2 มม.** ครบ 9 เงื่อนไข
> รายละเอียดอยู่ใน `manual-flow-counting.md` ข้อ 8

| | ถ่ายนิ่ง (ปัจจุบัน) | สดบนมือถือ |
|---|---|---|
| ความละเอียด warp | 8 px/มม. | 2.5 px/มม. |
| ความคลาด | −0.05 มม. | **±0.12 มม.** (สังเคราะห์) |
| เวลา | 16–18 วินาที | ~0.3 วินาที |

**ใช้ตัดสินเกรดได้ไหม?** เส้นแบ่งเกรดห่างกัน 3 มม. (22 / 25 / 28) และ sd อยู่ที่
0.2 มม. → **ตัดเกรดได้จริง ไม่ใช่แค่ช่วยดู**

ลูกที่อยู่ใกล้เส้นแบ่งภายใน **±0.3 มม.** ยังต้อง **ไม่เดา** — แสดงเป็น "ก้ำกึ่ง"
แล้วให้กดถ่ายนิ่ง กฎเดียวกับผลที่ซ้อนกัน: **นับได้ ไม่ได้แปลว่าวัดได้**

### การออกแบบสองระดับ

| โหมด | ใช้ทำอะไร | ความแม่น |
|---|---|---|
| **สด** | ช่วยคัดลงตระกร้า ดูภาพรวม | ±0.3 มม. · เกรดเชื่อได้ · ก้ำกึ่งไม่เดา |
| **ถ่ายนิ่ง** | บันทึกเป็นหลักฐาน ส่งผู้รับซื้อ | ±0.05 มม. · เก็บภาพไว้ |

สดคือ**คำแนะนำ** ถ่ายนิ่งคือ**บันทึก** สองอย่างนี้ต้องแยกกันให้ชัดในหน้าจอ

## 4. แผน 3 ระยะ

### ระยะ 1 — กรอบสดขณะเล็ง (ยังไม่วัด) · ~1 สัปดาห์

แสดงสดขณะส่องกล้อง: เจอมาร์กเกอร์กี่มุม · กรอบวัดอยู่ตรงไหนจริง · ภาพคมพอไหม ·
ไกล/ใกล้เกินไปไหม · **ปุ่มถ่ายกดไม่ได้จนครบ 4 มุม**

แก้ปัญหาที่หงุดหงิดที่สุดตอนนี้: ถ่าย → รอ 18 วินาที → เจอ *"ไม่พบมาร์กเกอร์"*
**ความล้มเหลวถูกค้นพบช้าที่สุดเท่าที่จะเป็นไปได้** ระยะนี้ย้ายไปตรวจก่อนกดชัตเตอร์
ที่ราคา 6 มิลลิวินาที

ใช้ opencv.js เฉพาะส่วน ArUco (อยู่ในโมดูล `objdetect` ตั้งแต่ OpenCV 4.7
ไม่ต้อง build contrib เอง — **ต้องยืนยันกับ build จริงก่อน**)

### ระยะ 2 — วัดสด · 3–5 สัปดาห์

- ย้าย pipeline ทั้งเส้นไป WASM ที่ 2.5 px/มม.
- แยกผลไม้ใน Web Worker ไม่ให้ค้างหน้าจอ
- แคชผล + ฉายใหม่ทุกเฟรมตามที่อธิบายข้อ 2
- ตรวจว่าฉากเปลี่ยนไหม (frame diff) เพื่อไม่ต้องคำนวณซ้ำโดยไม่จำเป็น
- ทำเครื่องหมาย "ก้ำกึ่ง" สำหรับลูกใกล้เส้นแบ่ง

**ความเสี่ยง:** ยังไม่เคยวัดว่า WASM ช้ากว่า native เท่าไรจริงในเคสนี้ —
ต้องทำ spike ทดสอบก่อน 2–3 วัน ก่อนตัดสินใจลงมือเต็มตัว

### ระยะ 3 — โมเดลแทน watershed · ต้องรอข้อมูล

จุดอ่อนจริงไม่ใช่ความเร็ว แต่คือ **ลำไยที่ซ้อนกัน** (วางเบียดเหลือวัดได้ 2%)
โมเดล instance segmentation แก้ได้ แต่ต้องมีภาพจริง 300–500 ใบพร้อม annotation

**ตอนนี้ `persisting: false` — ยังไม่ได้เก็บภาพจริงสักใบ**

## 5. ผลพลอยได้: ค่าเซิร์ฟเวอร์หายไป

ถ้าย้ายไปคำนวณบนเครื่อง **ไม่ต้องจ่าย Render สำหรับการวัดสดเลย** และ 18 วินาทีก็หายไป

แต่ยังต้องอัปโหลดภาพตอนกดถ่ายนิ่ง เพื่อเก็บเป็นชุดข้อมูลสำหรับระยะ 3
ไม่งั้นระบบจะไม่มีวันดีขึ้นกว่านี้
